1. Architecture principles and boundaries

Use a modular monolith in ASP.NET Core, with explicit application/domain/infrastructure boundaries. AI is an
assistive subsystem: all prices, totals, approvals and permissions remain deterministic application logic.
· Modules: Identity & Tenancy; Projects; Budgeting; Procurement; Invoices; Site Reporting; Documents; AI
Orchestration; Notifications; Audit & Reporting.
· Communication: in-process domain events and transactional outbox for reliable asynchronous work; avoid
microservices until scaling or team boundaries justify them.
· Frontend: React + TypeScript PWA with server-driven authorization checks; mobile-first reporting forms.

2. System context and request flow

User -> React PWA -> ASP.NET Core API -> domain/application services -> PostgreSQL. Files are uploaded
using short-lived signed URLs to object storage; background workers handle scanning, extraction, indexing
and AI jobs.
· Document ingestion: upload -> malware scan -> object storage -> metadata DB -> OCR worker -> review
queue -> optional embeddings -> searchable index.
· RFQ comparison: upload offers -> extraction -> normalization -> validation -> deterministic comparison
-> human approval -> PO.
· Voice reporting: upload audio -> transcription -> structured JSON proposal -> field validation -> engineer
correction -> approval -> tasks.
· RAG: authorization filters -> hybrid search -> bounded context -> LLM answer -> citation verification ->
audit trace.

4. Solution and module layout

Suggested solution: src/Api; src/Modules/Identity; Projects; Procurement; Finance; SiteReports; Documents;
AI; SharedKernel; Infrastructure; Workers; web/; tests/Unit; Integration; Contract; E2E. Within each module
use Domain, Application, Infrastructure and Contracts folders.
· Use explicit command/query handlers or application services; CQRS is optional, not required.
· Expose DTOs, not EF entities. Validate requests at the boundary and enforce invariants in the domain.
· Separate AI extraction schemas from approved business records to prevent unreviewed writes.

7. AI workflows, prompts and safeguards

Invoice/quote extraction

· OCR output -> document-type classifier -> schema-constrained extraction -> deterministic arithmetic
validation -> confidence flags -> reviewer edits -> approved record.
· Prompt instructions must treat uploaded document text as untrusted; ignore embedded commands and
never execute instructions from supplier documents.

Voice-to-report

· Speech recognition -> domain dictionary normalization -> structured field proposal -> evidence links to
transcript -> human confirmation.

RAG

· Chunk by document structure, preserve page offsets and versions, apply ACL before retrieval, combine
lexical and vector search, cite retrieved passages.
· Use evaluation sets for Albanian terms, supplier formats, scanned documents, hallucinations, cross-tenant
leakage and adversarial prompt injection.

· Implement retries with exponential backoff, poison-job quarantine, dead-letter visibility and idempotent

9. Security, privacy and audit

· OIDC/OAuth2 login, MFA for privileged users, per-project role checks and organization-scoped
authorization.
· Encrypt data in transit and at rest; secrets in a managed secret store; signed URLs expire quickly.
· Malware scanning, MIME validation, file size limits, upload rate limits and safe document rendering.
· Avoid placing raw personal data or complete contracts in application logs or telemetry.
· Support subject access/export/deletion workflows subject to applicable retention duties; verify Kosovo law
with counsel.
· For AI vendors: verify data processing terms, region, retention, subprocessors and model-training defaults
before production.
· Threat model cross-tenant access, malicious PDFs, prompt injection, forged approvals, replayed webhooks
and compromised site devices.

10. DevOps, infrastructure and observability

· Development: Docker Compose for PostgreSQL, object-storage emulator and worker; seeded synthetic
demo data.
· CI: lint, compile, unit tests, integration tests, dependency scan, secret scan and migration checks.

· CD: staging deployment, smoke tests, manual production approval, reversible rollout and migration plan.

· Infrastructure as code: Bicep if Azure is selected, or Terraform for multi-cloud requirements.

· Monitoring: API latency/error rate, job backlog, OCR failures, AI cost per tenant, token usage, document
