2. End-to-end customer journey

· 1. Owner registers an organization, selects locale, invites employees and creates a project.
· 2. Manager configures project budget, cost codes, milestones and approval thresholds.
· 3. Team imports existing supplier lists, budget spreadsheets and documents.
· 4. Procurement issues RFQs, receives quotations, compares normalized offers and submits a selection.
· 5. Site engineer logs daily progress, materials, blockers and photos, optionally by voice.
· 6. Finance reviews extracted invoices and matches them to orders or deliveries.
· 7. Manager reviews cost and schedule dashboards and approves corrective actions.
· 8. Owner exports a weekly project summary with linked evidence and open risks.

3. Project setup workflow

Trigger and prerequisites

Authorized manager creates a project. Required: project name, location at city level, start date, currency,
responsible manager; optional: estimated end date, project category, baseline budget.

Happy path

· Create draft project -> validate dates and permissions -> assign cost-code template -> invite members ->
set baseline -> activate.

4. Supplier quotation workflow

Detailed sequence

· Procurement creates RFQ with material description, unit, quantity, delivery date, specification and tax
handling.
· Suppliers send PDF/image/Excel quotations; user uploads or forwards into an authorized ingestion
channel.
· OCR extracts supplier, item, unit, price, VAT, delivery, currency and payment terms into a review queue.
· Normalize comparable units and flag ambiguous units, missing specifications and inconsistent tax
treatment.
· Display side-by-side quotes; compute totals deterministically; highlight cheapest compliant option but
never auto-select.
· Procurement submits recommendation -> approver accepts/rejects -> approved PO is generated -> audit
log retained.

Exceptions

· Unknown currency exchange rate: require a manually confirmed rate and date.
· Missing unit conversion or concrete grade mismatch: mark quotes non-comparable.
· Duplicate offer, expired validity or supplier withdrawal: warn and prevent silent overwrites.

5. Invoice and material receipt workflow

· 1. Upload invoice and delivery note; virus scan and store original.
· 2. Extract supplier, tax details, invoice number, lines, quantities, unit prices and totals.
· 3. Match supplier and PO; reconcile ordered vs delivered vs invoiced quantities.
· 4. Flag duplicates, mismatches, missing delivery evidence and unusual price differences.
· 5. Finance corrects and confirms; approved record updates actual costs, not merely AI output.
· 6. Export to accounting as CSV/API where available; record sync outcome and retries.

Acceptance criteria

· No invoice can be approved without a traceable source document and reviewer identity.
· Repeated invoice number for the same supplier generates a duplicate warning, with override rationale.

6. Daily site report workflow

· 1. Engineer selects project, site zone, date and shift.
· 2. Engineer types notes or records an Albanian voice memo; attaches photos and material receipts.
· 3. Transcription returns editable text with timestamps where supported.
· 4. AI proposes structured activities, workers, equipment, materials, blockers and safety observations.
· 5. Engineer edits fields and confirms factual accuracy; report is submitted.
· 6. Project manager reviews blockers and creates assigned follow-up tasks.
· 7. Weekly digest aggregates only approved daily reports and links to source entries.

Exceptions

· Low-quality audio or uncertain terms require manual confirmation; never invent quantities.
· Offline submissions should be queued locally only in a future offline-enabled release with encrypted
device storage.

7. AI document Q&A workflow

· 1. User uploads approved project documents with classification and access scope.
· 2. Processing extracts text, chunks it, stores embeddings and source offsets.
· 3. User asks a question; search filters documents by tenant, project and permission.
· 4. Assistant produces an answer with citations to document title, page/section and version.
· 5. When evidence is missing or conflicting, it abstains or highlights the discrepancy.
· 6. User can open the exact source, give feedback or flag a wrong answer.

Acceptance criteria

· No answer may cite documents the user is unauthorized to view.
· Answers about contractual responsibility require cited clauses and clear uncertainty language.

10. Non-functional requirements and UX

· Accessibility: keyboard support, sufficient contrast, clear form labels and readable mobile layouts.

· Localization: Albanian first; translations use reviewed construction vocabulary; dates, decimal separators
and EUR formatting are consistent.

· Performance target: typical dashboard under 3 seconds at pilot load; async documents show processing
status and retry actions.

· Availability objective for pilot: 99.5% monthly excluding announced maintenance; reassess before
contracted SLA.

· Security: least privilege, MFA for administrators, audit logs, encrypted transport and storage.

· Retention and deletion: configurable policies, legal-hold exceptions where applicable, and documented
export.

· AI quality: measure extraction field precision, transcription correction rate and unsupported answer rate
by document type.
